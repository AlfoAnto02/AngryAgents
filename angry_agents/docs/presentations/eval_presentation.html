Evaluation ideas

Personas, Fidelity, Context, and Reliable Metrics

A framework for assessing character consistency, evaluation robustness, and deliberation quality in long-form conversational AI systems.

01

The Core Problem

Long-form multi-agent conversations face two critical challenges:

Persona Drift

Agents converge to generic agreement or lose behavioral consistency over many turns, failing to maintain distinct, character-authentic viewpoints.

Evaluation Opacity

How do we rigorously measure whether agents stayed true to their personas, judges could distinguish them, and fidelity remained stable?

Why It Matters

  • Conversational AI systems are increasingly multi-turn and multi-character
  • Judges (human or AI) must reliably distinguish agent voices to assess quality
  • Metrics must be statistically robust and account for small sample sizes
02

Preventing Groupthink: Perturbations & Drift Detection

The system uses two mechanisms to maintain persona diversity over time:

Perturbations

Every N turns (randomized 10–15), inject a hidden prompt: "React in a way that reflects your genuine position, even if it means disagreeing."

→ Forces character-consistent friction

Drift Detection (Optional)

Compute pairwise cosine similarity across all agent embeddings:

drift_score = mean(
cosine_sim(agenti, agentj))
for all i ≠ j

If drift_score > 0.85 → fire perturbation early

Outcome

Agents remain distinguishable and maintain separate viewpoints even after many turns, producing evaluable conversations that don't collapse into consensus.

03

How Many Tags Should Judges See?

The persona identification task depends critically on the candidate set shown to judges. Three design choices exist, each with different statistical and practical implications.

Option A — Closed Set

Judges receive exactly the 8 tags present in the chat. It's a forced-choice assignment: every tag must be used exactly once.

Random baseline = 1/8 ≈ 12.5%
All 8 tags guaranteed used
No "none of the above" option

✓ Cleanest statistic
✗ Artificially constrains the task

Option B — Expanded Set

Judges receive K > 8 tags (e.g., 12 o 16), including decoys not present in the chat. They must identify which 8 belong.

Random baseline = 1/K per tag
= 1/12 ≈ 8.3% (K=12)
Lower floor → harder task

✓ More realistic
✗ Harder to aggregate stats

Option C — Full Database

Judges choose from the entire agent database (N agents). No pre-selection: the judge must identify all 8 personas from scratch.

Random baseline ≈ 8 / N
C(N,8) possible assignments
Near-zero random baseline

✓ Most ecologically valid
✗ Cognitive overload on judges

Statistical Impact

The random baseline changes with the candidate set size. Option A gives the highest baseline (12.5%), making it easier to show significance. Options B and C lower the baseline, so a given accuracy looks more impressive — but the task itself is harder, meaning raw accuracy will also drop. The binomial CI and chi-square test still apply in all cases; only the H₀ value changes.

Recommendation

A pragmatic middle ground: use Option B with a fixed K (e.g., K = 16, so 8 correct + 8 decoys drawn randomly from the DB). This keeps the task tractable for judges, keeps the random baseline stable and well-defined (1/16 per tag = 6.25%), and better reflects real-world disambiguation conditions than a closed forced-choice.

04

How Should Judges Submit Their Guess?

Once a judge has read the conversation, how should the identification response be structured? A point guess is simple but lossy — a scored ranking preserves richer signal at higher cost.

Option A — Hard Guess

The judge assigns each anonymous tag to exactly one persona name. One answer per tag, no probability or confidence expressed.

Input: tag_i → persona_j (1-to-1 mapping)
Output: correct / wrong (binary per tag)
Metric: accuracy = k correct / n total

✓ Minimal tokens — fast, cheap
✓ Simple metric (binomial CI applies directly)
✗ No signal when wrong — all errors look equal
✗ "Almost right" guesses indistinguishable from random

Option B — Fidelity-Scored Ranking

For each tag, the judge scores every candidate persona on fidelity (1–5). The persona with the highest total score becomes the hard guess; the full ranking is also recorded.

For each tag_i: score(persona_j) ∀ j ∈ K
guess = argmax_j score(tag_i, persona_j)
Output: ranked list + hard guess

✓ Richer signal even when wrong
✓ Ranking enables Spearman / NDCG metrics
✓ Naturally integrates with fidelity scoring
✗ K × 8 scoring calls → token cost scales with K
✗ Judge prompt complexity grows significantly

Token Cost Scaling

Option A costs O(1) per tag. Option B costs O(K) per tag — with K = 16 candidates and 8 tags, each judge produces 128 individual fidelity scores per conversation. Multiplied across 20 judges, this is a significant token budget increase.

Interaction with Candidate Set

Option B's cost is directly coupled to the candidate set size K chosen in the previous design decision. Closed set (K = 8) → 64 scores/judge. Expanded set (K = 16) → 128 scores/judge. Full DB (K = N) → prohibitive. Option B only makes sense with a bounded K.

Recommended Approach

Use Option A for the identification task (hard guess only) and keep fidelity scoring in the dedicated Pool 2. Mixing scoring into the identification task inflates complexity without proportional gain — the ranking signal is already captured more cleanly by Pool 2's targeted fidelity prompts.

Step 1: Can Judges Identify Personas?

Given 8 anonymous author tags and 8 personas, do judges match them correctly?

Baseline (Random): 1/8 = 12.5% accuracy
Statistical Test: Binomial exact confidence interval (Clopper-Pearson method) to assess if judges are significantly better than random.
Confusion Matrix: 8×8 matrix tracking which personas are confused with which. Chi-square test reveals whether mistakes are random or systematic.
H₀: true accuracy = 0.125
H₁: true accuracy > 0.125 (one-sided)
p-value < 0.05 → Reject H₀

✓ If judges pass: personas are distinguishable and evaluation can proceed reliably

05

Step 2: How Faithfully Did Agents Portray Characters?

Judges score each persona (1–5). We aggregate to summarize "true" fidelity, but face an aggregation choice.

Median vs. Mean: Fidelity scores are ordinal. We are still not fully certain whether median or mean is the best aggregation strategy. Median is robust to outliers; mean respects interval structure. Neither is definitively superior.
IQR & Variance: Spread measures (IQR = Q3 − Q1, sample variance) reveal judge disagreement. Large IQR = fuzzy fidelity.

Bootstrap 95% CI on Median

Resample scores 10,000× with replacement
For each resample: compute median
CI = [percentile(2.5%), percentile(97.5%)]

Non-parametric, works with small samples, no distributional assumptions needed.

Step 3 & 4: Does the Group Stay Diverse? Do Judges Learn?

Gini Coefficient (Turn Distribution)

Measures inequality: agents taking equal turns (Gini = 0) vs. one agent dominating (Gini = 1).

Gini = (2Σi i·counti)/(n·total)
− (n+1)/n

Target: 0.28–0.42

Cosine Distance & Embeddings

Build 8×8 distance matrix: how different is each agent's language from others?

dist = 1 − (vi·vj)
/ (‖vi‖ × ‖vj‖)

Compare simulated to reference via Spearman ρ.

Deliberation & Convergence

In Phase 2, do judges discuss and agree more?

Δvar = var(round0) − var(roundfinal)
converged = Δvar > 0

F-test: is reduction significant?

07

Confidence Calibration & Reliability

As judges become more confident through deliberation, do they actually become more accurate?

Calibration Correlation: Pearson r between Δconfidence and Δaccuracy. Positive r = good (confidence → accuracy). Negative r = overconfidence flag.
Confidence Curves: At each confidence level (1–5), what fraction of (judge, case) pairs got the answer right? Well-calibrated judges: high confidence → high accuracy.

Key Takeaways

  • Perturbations + drift detection maintain persona diversity and prevent collapse to consensus
  • Statistical rigor (binomial CIs, bootstrap, Spearman rank) avoids overconfident conclusions from small samples
  • Aggregation strategy is still open: median vs. mean trade-offs warrant transparency and sensitivity analysis
  • Multi-faceted evaluation (identification, fidelity, group dynamics, deliberation, calibration) captures conversation quality comprehensively
  • Systematic evaluation frameworks enable reliable assessment of multi-agent conversational AI at scale
08

How Should Individual Fidelity Be Measured?

Two competing designs exist for collecting fidelity scores (1–5). The choice affects prompt specificity, cognitive load, and evaluation cost.

Option A — Sequential (Same Judges)

The same 20 judges first perform the blind persona-identification guess. Then they are shown the correct author map and retrospectively score each agent on fidelity (1–5).

Phase 1 → blind guess (identification)
Phase 2 → reveal correct map
Phase 3 → fidelity score per agent

✓ Lower cost — one judge pool
✓ Same judge sees both tasks → richer signal
✗ Anchoring bias: knowing the answer may inflate scores
✗ Prompt must serve two goals → less focused

Option B — Parallel (Dedicated Judge Pools)

Two separate judge pools with distinct prompts. Pool 1 (20 judges): blind identification only. Pool 2 (N judges): shown persona descriptions upfront, score fidelity directly.

Pool 1 → identification task only
Pool 2 → fidelity task only
(persona info given from the start)

✓ Each prompt is laser-focused → better signal
✓ No anchoring between tasks
✓ Pool 2 can use fewer judges (4 types × N)
✗ Higher total cost — two separate runs

Anchoring Risk

In Option A, after seeing the correct answer a judge's fidelity score may reflect "I should have guessed this" rather than genuine character consistency. This inflates scores and correlates them with identification accuracy — conflating two separate signals.

Prompt Contamination

A single judge receiving both tasks needs a prompt that covers identification logic and fidelity rubrics. This makes the prompt longer, noisier, and harder to validate. Option B allows each prompt to be minimal and purpose-built.

Recommended Approach

Prefer Option B if budget allows. For Pool 2, 4 judge types × 3–5 judges each (12–20 total) is sufficient for stable median + bootstrap CI. The extra cost is modest relative to the gain in signal cleanliness and construct validity.
