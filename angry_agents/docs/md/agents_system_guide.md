# Group Chat Agent System — Architecture Guide

## Overview

This document defines the architecture for the persona-agents that participate in group chats.
The core challenge is keeping agents faithful to their extracted persona profiles across a
multi-turn conversation, while writing to the DB in a way that preserves judge-facing anonymity.

Design constraints (from CLAUDE.md and the experimental pipeline):
- Never call the LLM on every tick — only when it is that agent's turn.
- SQL lives in `api/` only. Agents receive plain Python objects, not DB handles.
- `Chat_messages.author` is an HMAC token — no FK to `Agents`. Generated by `ChatMessageService`.
- Phase 1 evaluation must be possible without judges knowing which persona maps to which author.

## DB Mapping

### Domain types

All internal code uses **model dataclasses** from `src/db/models/` — never the Pydantic `Out`
schemas from `src/API/schemas.py`, which are API-layer only.

| Domain type | Module | Used as |
|---|---|---|
| `Agent` | `db/models/agents.py` | Identity: `name`, `surname`, `id`, `summary` |
| `AgentContext` | `db/models/agent_context.py` | Profile chunk: `signature_phrases` (JSON string) |
| `ChatMessage` | `db/models/chat_messages.py` | One message row: `author`, `message`, `id_chat` |
| `Topic` | `db/models/topic.py` | Topic: `title`, `description` |
| `GroupChat` | `db/models/group_chat.py` | Session row: `id_topic` |

### Services

All DB access goes through service classes from `src/db/services/`. Each service wraps a
repository and adds business logic. They are instantiated per-call with a `db` connection.

| Service | Constructor | Relevant method |
|---|---|---|
| `AgentService` | `AgentService(db)` | `.get(id)`, `.query(filters={"id_topic": ...})` |
| `AgentContextService` | `AgentContextService(db)` | `.query(filters={"id_agent": ...})` |
| `ChatMessageService` | `ChatMessageService(db, author_secret)` | `.create(id_chat, message, agent_id=...)`, `.query(filters={"id_chat": ...})` |
| `TopicService` | `TopicService(db)` | `.get(id)` |
| `GroupChatService` | `GroupChatService(db)` | `.get(id)` |

`ChatMessageService` is the only service that takes a second argument: `author_secret`.
This is the `ANGRY_AUTHOR_SECRET` environment variable, accessed via `Settings` from
`src/API/config.py`. Callers must thread it through — the same pattern used in the route layer.

### Author anonymisation

`ChatMessageService.create(..., agent_id=agent_id)` handles author token generation
internally: it fetches `name` and `surname` from the `Agents` table and computes
`HMAC-SHA256(secret, name:surname)`. The agent layer never builds the token itself.
`Chat_messages.author` has no FK to `Agents` by design — judges see source diversity
without knowing real agent identity.

### Agent_context population

The extraction pipeline stores the structured persona profile across multiple `Agent_context`
rows per agent. Recommended grouping (maps onto the judge role split):

| `Agent_context` row | `signature_phrases` keys |
|---|---|
| row 1 — style | `core_style`, `humor`, `vocabulary_markers`, `exemplar_quotes` |
| row 2 — ideology | `ideological_positions`, `emotional_triggers` |
| row 3 — social | `response_patterns`, `social_positioning` |

### `Agents.Summary` (per-chat state)

`Summary` is a JSON text column. Since the same `Agent` row can participate in multiple
chats (same topic, different `Group_chat.ID`), state is namespaced by `chat_id`:

```python
{
    "<chat_id>": {
        "key_positions": ["string", ...],
        "emotional_state": "engaged",
        "turn_count": 12,
    }
}
```

`AgentService(db).update(agent_id, {"summary": json.dumps(new_summary)})` writes it back.
Updated every 10 turns, not on every message.

```
GroupChatFactory
    └── build_session(db, chat_id, model, author_secret, ...) → GroupChatSession

GroupChatSession
    ├── chat_id: int
    ├── topic: Topic
    ├── agents: list[PersonaAgent]
    ├── scheduler: TurnScheduler

    ├── strategy: "rolling" | "selective"
    └── max_messages: int

TurnScheduler
    ├── strategy: "round_robin" | "weighted_random"
    └── _index: int
```

## `PersonaAgent` (`src/agents/personas/persona_agent.py`)

```python
@dataclass
class PersonaAgent:
    agent: Agent
    contexts: list[AgentContext]
    model: str

    def bind_to_chat(self, _chat_id: int, topic: Topic) -> None:
        """Precomputes _persona_name, _profile_block, _topic_block and dominance_weight.
        Called once before the chat starts — JSON parsing happens here, not per turn."""

    def respond(self, history: list[ChatMessage], turn_count: int = 0) -> str:
        """Renders persona_chat.j2 with cached profile + per-turn history, then calls llm_call().
        One LLM call per turn."""

    def update_summary(self, chat_id: int, _new_message: str, current_summary: dict) -> dict:
        """Updates the per-chat state dict. Caller writes it to DB via AgentService."""
```

### Template system (`src/agents/personas/templates/`)

Prompt text lives in Jinja2 templates, not in Python — same pattern as the judge pipeline.
`render_prompt(template_name, **kwargs) -> (system, user)` is defined in `templates/__init__.py`
and is identical in structure to `src/agents/judges/templates/__init__.py`.

**`persona_chat.j2`** — variables: `persona_name`, `profile_block`, `topic_block`, `history_block`, `reground` (bool)

```
{%- block system -%}
You are {{ persona_name }}.
You are participating in a group conversation with other people. You do not know who they are.

## Your profile
{{ profile_block }}

## Conversation topic
{{ topic_block }}

## Rules
- Write exactly one message, as {{ persona_name }} would naturally write it.
- Never mention that you are an AI, a language model, or that you are playing a role.
- Stay consistent with your vocabulary, tone, ideological positions, and emotional patterns.
- React to the most recent messages — agree, push back, deflect, joke, or ignore as your profile dictates.
- If the topic does not interest {{ persona_name }}, write a short, dismissive reply. Do not force enthusiasm.
- Do not summarise or echo what others said. Respond to it.
- Write in first person. Do not sign your message.
{%- endblock -%}

{%- block user -%}
--- CONVERSATION SO FAR ---
{{ history_block }}

--- YOUR TURN ---
{% if reground %}
[Stay true to who you are — {{ persona_name }}. Your voice and positions must remain consistent.]
{% endif %}
Respond as {{ persona_name }}.
{%- endblock -%}
```

### How `respond()` uses the template

```python
def respond(self, history: list[ChatMessage], turn_count: int = 0) -> str:
    from ..agent_config import llm_call

    history_block = "\n".join(f"[{m.author or 'User'}]: {m.message}" for m in history)
    reground = turn_count > 0 and turn_count % 20 == 0
    system, user = render_prompt(
        "persona_chat.j2",
        persona_name=self._persona_name,
        profile_block=self._profile_block,
        topic_block=self._topic_block,
        history_block=history_block,
        reground=reground,
    )
    return llm_call(system, user, self.model)
```

The three cached fields (`_persona_name`, `_profile_block`, `_topic_block`) are set once in
`bind_to_chat()`. `history_block` and `reground` are the only per-turn variables.

## `AgentFactory` (`src/agents/personas/factory.py`)

```python
class AgentFactory:

    @staticmethod
    def from_db(db, agent_id: int, model: str) -> PersonaAgent:
        agent    = AgentService(db).get(agent_id)
        contexts = AgentContextService(db).query(filters={"id_agent": agent_id})
        return PersonaAgent(agent=agent, contexts=contexts, model=model)

    @staticmethod
    def for_chat(db, chat_id: int, model: str) -> list[PersonaAgent]:
        chat       = GroupChatService(db).get(chat_id)
        topic      = TopicService(db).get(chat.id_topic)
        agent_rows = AgentService(db).query(filters={"id_topic": chat.id_topic})

        agents = []
        for row in agent_rows:
            agent = AgentFactory.from_db(db, row.id, model)
            agent.bind_to_chat(chat_id, topic)
            agents.append(agent)
        return agents
```

All service calls follow the `ServiceClass(db).method()` pattern — no standalone functions.

## `ContextWindow` (`src/group_chat/context_window.py`)

```python
class ContextWindow:
    def __init__(self, strategy: Literal["rolling", "selective"], max_messages: int = 40): ...

    def trim(self, history: list[ChatMessage], agent: PersonaAgent) -> list[ChatMessage]:
        if len(history) <= self.max_messages:
            return history
        if self.strategy == "rolling":
            return history[-self.max_messages:]
        k = self.max_messages // 4   # preserve opening (topic framing)
        n = self.max_messages - k    # fill with recency
        return history[:k] + history[-n:]
```

`rolling` — last N messages. Simple; loses topic framing. Use for short chats (< 40 turns).
`selective` — first K + last N. Recommended default; agents cannot forget the topic.

## `TurnScheduler` (`src/group_chat/scheduler.py`)

```python
class TurnScheduler:
    def __init__(self, agents: list[PersonaAgent], strategy: Literal["round_robin", "weighted_random"]): ...

    def next(self) -> PersonaAgent:
        if self.strategy == "round_robin":
            agent = self.agents[self._index % len(self.agents)]
            self._index += 1
            return agent
        weights = [a.dominance_weight for a in self.agents]
        return random.choices(self.agents, weights=weights, k=1)[0]

    def mark_spoke(self, agent: PersonaAgent) -> None: ...
```

`dominance_weight` is parsed from `social_positioning` in `AgentContext` at `bind_to_chat()`
time (`"assertive"` → 0.7, `"reserved"` → 0.3, default 0.5). No DB read during the loop.

## `GroupChatSession` (`src/group_chat/session.py`)

```python
@dataclass
class GroupChatSession:
    chat_id: int
    topic: Topic
    agents: list[PersonaAgent]
    scheduler: TurnScheduler
    context_window: ContextWindow
    author_secret: str

    def run(self, db, n_turns: int, on_message: Callable[[ChatMessage], None] | None = None) -> list[ChatMessage]:
        ...

    def run_turn(self, db) -> ChatMessage:
        svc = ChatMessageService(db, self.author_secret)
        agent = self.scheduler.next()
        self._turn_count += 1

        history = svc.query(filters={"id_chat": self.chat_id})
        trimmed = self.context_window.trim(history, agent)
        content = agent.respond(trimmed, turn_count=self._turn_count)
        msg     = self._write_message(svc, agent, content)

        self.scheduler.mark_spoke(agent)

        if self._turn_count % 10 == 0:
            current = json.loads(agent.agent.summary or "{}")
            updated = agent.update_summary(self.chat_id, content, current)
            AgentService(db).update(agent.agent.id, {"summary": json.dumps(updated)})

        return msg

    def _write_message(self, svc: ChatMessageService, agent: PersonaAgent, content: str) -> ChatMessage:
        return svc.create(
            id_chat=self.chat_id,
            message=content,
            agent_id=agent.agent.id,  # service computes HMAC author token internally
            created_by=None,
        )
```

## `GroupChatFactory` (`src/group_chat/group_chat_factory.py`)

The single wiring entry point. Callers get `author_secret` from `get_settings().author_secret`
and pass it in — same pattern as `_svc(db, settings)` in the existing route layer.

```python
class GroupChatFactory:

    @staticmethod
    def build_session(
        db,
        chat_id: int,
        model: str,
        author_secret: str,
        scheduler_strategy: Literal["round_robin", "weighted_random"] = "weighted_random",
        window_strategy: Literal["rolling", "selective"] = "selective",
        max_messages: int = 40,
    ) -> GroupChatSession:
        chat   = GroupChatService(db).get(chat_id)
        topic  = TopicService(db).get(chat.id_topic)
        agents = AgentFactory.for_chat(db, chat_id, model)

        return GroupChatSession(
            chat_id=chat_id,
            topic=topic,
            agents=agents,
            scheduler=TurnScheduler(agents, scheduler_strategy),
            context_window=ContextWindow(window_strategy, max_messages),
            author_secret=author_secret,
        )
```

## Persona Drift Mitigation

Three layered defences:

1. **Prompt anchor** — The persona's name and identity appear in both the system and user
   blocks of `persona_chat.j2`. The system block is rebuilt each turn, so it is never stale.

2. **Selective context window** — First K messages preserve the topic framing across the
   full chat length. Agents cannot drift away from the original topic.

3. **Periodic re-grounding** — Every 20 turns, `respond()` sets `reground=True`, which
   activates the `{% if reground %}` block in the user template, injecting a one-line
   reminder. No extra LLM call — one conditional line in the existing user message.

## Sequence: One Agent Turn

```
GroupChatSession.run_turn(db)
    │
    ├─ scheduler.next()                                    → PersonaAgent
    │
    ├─ ChatMessageService(db, author_secret)               instantiated
    │
    ├─ svc.query(filters={"id_chat": chat_id})             → list[ChatMessage]   (DB read)
    │
    ├─ context_window.trim(history, agent)                 → list[ChatMessage]   (pure)
    │
    ├─ agent.respond(trimmed, turn_count)
    │      ├─ render_prompt("persona_chat.j2", ...)        → (system, user)      (template render)
    │      └─ llm_call(system, user, model)                → str                 (LLM call)
    │
    ├─ svc.create(id_chat, message, agent_id=..., ...)     → ChatMessage         (DB write)
    │      └─ internally: fetches Agent name+surname, computes HMAC author token
    │
    └─ [every 10 turns] AgentService(db).update(id, {"summary": ...})            (DB write)
```

One LLM call per turn. Two DB operations per turn (one read, one write), plus an
occasional third for the summary update.
